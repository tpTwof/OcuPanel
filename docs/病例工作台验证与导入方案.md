## 眼科分析结果填入病例：待实现方案

建议增加「从已保存分析创建草稿 / 补充当前病例」，先预览再确认。首期读取已有存档，不重复推理、不额外调用 LLM。

### 用户流程

1. 在眼科分析结果旁提供「用于病例草稿」；工作台提供「选择已有分析」。两处进入同一导入预览。
2. 选择当前账号的已保存分析，明确就诊编号、采集时间、设备与左右眼。**旧报告缺少可靠眼别，必须人工确认；不能由文件名或模型推断。** 双眼分别选择来源，缺少的一眼保留未拍或未评估。
3. 预览可带入的病例备注、病种、模型测量及来源，标明缺项、研究状态和引用校验状态。已有人工填写内容默认保留，冲突项由用户逐项决定是否覆盖。
4. 确认后生成新的病例草稿版本，所有导入所见保留「模型研究结果」身份；人工评估结论仍待复核。导入不能自动完成复核、签发或转诊。
5. 后续追问和导出继续引用病例版本；可展开查看原报告 ID、生成时间、模型版本、引用校验结果和本次人工修订。

### 字段如何处理

| 原分析内容 | 拟带入位置 | 保留的边界 |
| --- | --- | --- |
| 临床记录 | 病例备注的可选候选内容 | 标明来源，由用户确认，不替换已有备注。 |
| 已选择病种及 visual_findings | 本眼对应任务的只读「研究分析」区 | 与人工所见分开保存；不借青光眼结果填写其他任务。DME 无模型结果时保持未评估。 |
| 青光眼概率、面积等效 CDR | 原值、原单位和计算定义 | 不套用垂直 CDR 阈值，不据此分期、排除或自动决定转诊。 |
| DR/AMD FLAIR 分数 | 研究匹配指标 | 不转换为阳性、阴性、分级、质量或临床置信度。 |
| summary、evidence、verification | 原报告的只读版本引用 | 引用校验不等于人工复核；拒答、disabled 或 error 必须显式保留，不能作为通过的临床计划。 |
| img_name 对应的叠加图 | 辅助图预览 | 叠加图不是原图。当前旧报告未归档原图时应显示缺项，不能伪造已核对原图。 |
| report_id、模型及软件版本 | 新的导入来源记录 | 服务端按账号核对归属，保存不可变来源快照及哈希，后续更新不改写旧病例。 |

### 需要补建的接口与契约

- 增加当前账号的报告列表与结构化详情接口，返回可导入字段和缺项，不暴露其他账号数据。
- 为病例新增独立的 `analysis_sources` / `model_findings` 契约，保存原报告、绑定眼别、模型版本和原始数值；**不能把这些值直接写成当前 `human_rehearsal` 人工记录**。
- 先补齐原图安全存储或机构影像引用及采集元数据。历史记录没有原图时只作为研究信息导入，保持原图缺失和待复核状态。
- 提供带目标病例版本及幂等键的「预览确认后导入」接口。重放不重复追加来源；版本冲突返回 409；导入只创建草稿，不改变既有签发或转诊记录。
- 继续保持合成演练与真实数据准入边界。真实病例导入须在机构数据授权、存储权限及角色要求落实后另行启用，不能通过导入接口绕过现有 synthetic 限制。

### 下一轮验收场景

同一报告重复导入；两个账号交叉访问；只导入右眼而左眼缺失；双眼来源不同；原图缺失；报告拒答或校验关闭；FLAIR 低分但任务仍未评估；已有人工所见与模型信息冲突；导入途中断网；导入后修改及历史导出一致性。这些是方案的验收要求，**本轮没有运行或宣称通过导入测试**。
