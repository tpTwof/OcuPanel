# OcuPanel 课题阶段性汇报

**汇报主题**　基于眼底影像和临床记录的眼科报告原型  
**建议用时**　约 6 分钟，含演示

## 1. 课题目标｜约 40 秒

老师好，我们这阶段关注的是：能否把彩色眼底照、临床记录和检索到的参考资料放进同一份报告，让阅读者能看清哪些内容来自模型测量、哪些来自病例记录、哪些有资料支持。

课题启动后，我们先做了一轮初步文献查找。我在此基础上搭建了 OcuPanel 原型，先选青光眼场景，把上传、影像分析、报告生成和引用核查串起来。今天主要汇报这条流程能演示到哪一步，以及后面怎么验证结果。

## 2. 项目来源与已完成工作｜约 1 分钟

OcuPanel 最初 fork 自 Purdue M2 Lab 的 MedChat。青光眼报告沿用了原项目的六个专科角色，以及由 Director 汇总专科意见的设计。六个角色包括眼科医生、验光师、青光眼专科医生、全科医生、眼科技师和药师。 [MedChat 源码](https://github.com/Purdue-M2/MedChat) · [原始论文](https://doi.org/10.1109/MIPR67560.2025.00078)

我这阶段主要做了三件事。

1. **加入证据检索和引用核查。** 生成报告时检索相关资料，对照证据检查报告中的外部知识陈述。引用缺失或校验失败时，界面可以展示拒答原因。
2. **接通账号、会话和报告页面。** 报告可以进入当前会话，用户可以展开证据、继续追问，也可以下载通过校验的报告。
3. **检查原型能否稳定执行。** 已在仓库示例图上运行青光眼视觉模型，得到分类输出、视杯视盘分割和面积等效杯盘比。本地前端构建成功，52 项离线后端测试通过。这些结果验证了示例推理和软件行为，临床表现仍需独立评估。 [影像验证记录](../backend/vision/README.md#本地真实模型验证)

## 3. 演示｜约 2 分钟

**演示材料**　使用仓库内带 AI 生成水印的眼底照和示例临床记录。 [眼底照](../samples/fundus_right_eye.png) · [临床记录](../samples/clinical_note.txt)

1. 打开「眼科分析」，上传示例眼底照，粘贴临床记录，提交青光眼分析。
2. 结果出来后，展示分割叠加图和面积等效杯盘比，然后打开报告中的一条引用，说明对应资料支持的是哪一句。
3. 如果系统拒答，直接展示原因，说明系统在证据不足或校验未通过时如何处理。如果现场服务响应较慢，使用提前生成的演示结果，并说明它来自同一份示例输入。

**演示时可以这样讲**

> 这里的分割图和杯盘比来自视觉模型，病例背景来自刚才填入的临床记录，报告中的引用则对应系统检索到的资料。我们可以打开一条引用，检查它是否支持报告里的说法。分割结果和临床判断的准确性还需要拿独立标注病例来验证。

## 4. 当前缺口｜约 1 分钟

| 当前缺口 | 对本次汇报的影响 |
| --- | --- |
| 缺少独立标注病例 | 目前能说明示例流程已跑通，尚无本项目在独立病例上的识别准确率、漏检率或分割表现。 |
| 影像质量判断有限 | 现有输入检查主要拦截明显异常，仍需评估模糊、曝光不当、视野覆盖不足等不可判读情况。 |
| 证据覆盖与校验有局限 | 校验依赖检索到的材料和模型判断，需要人工抽查引用是否支持对应陈述，以及证据不足时系统是否正确拒答。 |
| 多病种仍在本地探索 | 糖尿病视网膜病变和年龄相关性黄斑变性目前只有 FLAIR 图文匹配分数，缺少临床校准、阈值和独立病例验证。本次以青光眼作为演示主线。 [本地模型说明](../backend/vision/README.md#当前缺陷) |

## 5. 下一阶段｜约 1 分钟

1. **先确定青光眼验证任务。** 建议先做一个有独立参考标注的小规模验证，记录图像可判读性，并分别核对视觉输出和报告内容。
2. **把影像和报告分开评估。** 有分割标注时比较视杯、视盘分割与杯盘比误差。报告按病例信息一致性、引用是否支持陈述、证据不足时是否正确拒答逐项记录。
3. **对比检索的实际作用。** 对同一批病例使用相同模型，比较启用检索与引用校验后的报告与基础生成结果，汇总引用错误和拒答情况。根据青光眼的验证进展，再决定多病种探索的优先级。

**结束语**

> 这阶段已经搭建了一个可以现场演示的青光眼报告原型。接下来，我们准备把示例演示推进到独立病例验证，先明确影像输出和报告分别怎么评估。也想请老师帮我们确认，下一阶段是否先集中做好青光眼场景，以及有哪些合适的数据和标注资源可以使用。

## 备答

**这个项目和 MedChat 有什么关系？**  
OcuPanel 基于 MedChat 开发。上游提供了视觉分析和多角色汇总方案，这阶段的扩展主要集中在证据检索、引用校验、账号和会话持久化。

**现在能判断模型准不准吗？**  
现在有单个示例的视觉推理记录和软件回归测试结果。识别、分割和报告质量都需要在独立、有参考标注的病例上分别评估。

**如果时间有限，下一步优先做什么？**  
先围绕青光眼准备第一批独立样本和评估表，完成一轮可复查的小规模验证，再根据错误类型决定先改影像处理、证据检索还是报告生成。
