# 报告流程基线与评估记录

日期：2026-11-26  
状态：实施记录。数值只描述本机、固定输入下的软件行为，不是临床性能结论。

本文件对应[报告生成与语料库改造方案](报告生成与语料库改造方案.md)阶段一的交付物：覆盖缺口表、评估病例集与基线记录。覆盖表见[语料覆盖矩阵](语料覆盖矩阵.md)，评估病例集见 [`backend/tests/fixtures/report_eval_cases.json`](../backend/tests/fixtures/report_eval_cases.json)。

## 1. 基线口径

旧流程（`REPORT_PIPELINE=legacy`）的已知运行记录来自[架构说明](ARCHITECTURE.md)与 [ADR-0002](adr/0002-agent-runtime-langgraph.md)：

| 指标 | 旧流程记录 | 说明 |
| --- | --- | --- |
| 单份报告耗时 | 38–74 秒，平均 58 秒 | 青光眼单病种，`deepseek-flash`，关闭推理（`LLM_DISABLE_THINKING=1`） |
| 交付率 | 5/6 | 同一批固定病例，软标注交付开启 |
| 模型调用 | 约 8–10 次/份 | 专科撰稿 + 综合 + 核查/修订轮次 |
| 检索 | 每病种固定 4 个主题查询 | 诊断评估、判读、处置、随访，与病例无关地全量检索 |

这些数字不能直接与真实病例或他人环境比较：模型、端点、语料版本与病例都会改变结果。

## 2. 结构基线（可离线复核）

流程结构由代码固定，可离线断言，不依赖模型输出。`backend/tests/test_report_pipeline_v2.py` 覆盖：

| 行为 | 旧流程 | 新流程（v2） |
| --- | --- | --- |
| 检索触发 | 每个病种固定检索 | 由检索计划决定；`need_retrieval=false` 不检索 |
| 查询数 | `4 × 病种数` | `≤ RETRIEVAL_PLAN_MAX_QUESTIONS`，总量受 `RETRIEVAL_MAX_QUERIES` 限制 |
| 补检 | 无 | 每个缺口最多补检一次；相同查询不重复执行 |
| 证据条数 | `RAG_TOP_K`（12） | `RETRIEVAL_MAX_EVIDENCE`（12），补检追加编号 |
| 证据适用性 | 仅按来源病种过滤 | 病种（条款级优先）+ 材料类型 + 适用条件 |
| 故障语义 | 检索异常退化为「不注入证据」 | `tool_error` 与「无结果」分开记录；全查询失败时只交付病例摘要 |
| 报告提示词 | 单病种/综合共用固定文本 | 版本化统一约束（`REPORT_PROMPT_VERSION`），写入校验记录 |
| 模型调用 | 约 8–10 次/份 | 在上述调用之外增加 1 次检索规划调用；v2 的完整调用数与耗时需重新测量，不沿用旧数字 |
| 存档字段 | 证据正文、校验记录 | 追加检索计划、覆盖缺口、病例事实摘要、材料类型与审核状态 |

说明：`RETRIEVAL_MAX_EVIDENCE` 与旧流程的 `RAG_TOP_K` 默认值相同，避免把「检索方式变化」与「证据预算变化」混在一起比较。

## 3. 评估方法

1. **固定工具结果验证流程与状态**：用构造的检索结果覆盖无结果、工具故障、补检、预算耗尽、重复查询、不适用来源、左右眼混淆与未知引用编号，断言状态、证据编号与存档字段，不调用真实模型。
2. **固定病例回放**：`test_glaucoma_cases.py` 等既有回放继续验证影像测量、证据编号与核查状态；新增流程的固定病例在 `test_report_pipeline_v2.py` 中。
3. **经审核病例集评估真实模型输出**：用 `report_eval_cases.json` 的固定输入跑真实模型，人工核对初步评估、引用与建议适用性。临床解释质量与建议适用性需要专业复核，不能仅由另一个模型评分。
4. 量化阈值（耗时、检索次数、token 用量）在积累基线后确定；本文件不预先承诺准确率或性能提升。

## 4. 已知限制

- 语料条款多为章节摘要，审核状态为「待复核」；引用校验通过不等于临床有效。
- 覆盖矩阵按条款级元数据统计，材料类型与主题缺失时按未登记处理，不能据此宣称覆盖完整。
- 评估病例为合成或固定输入，不代表真实患者分布，也不能验证影像模型本身的准确性。
- 相似病例检索、自主处方、未经审核内容自动入库与新增病种视觉诊断不在第一版范围内。
