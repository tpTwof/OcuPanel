## 接手时统一使用的口径

| 讨论事项 | 产品、研发和临床共同使用的含义 |
| --- | --- |
| 一次检查 | 以机构内就诊编号关联采集时间、设备、眼别和原图。左右眼分别记录可见范围、质量、所见和去向。追问、PDF 和转诊单须引用具体报告版本。 |
| 不可判读 | 指某只眼的某项任务所需区域看不清。写明原因和重拍或人工检查安排。未拍、未评估、不可判读、可判读且未见目标征象分别保存。 |
| 青光眼筛查 | 新方法的目标是识别值得复核的视神经损伤征象。旧分类分数用于对照。面积等效杯盘比保留原名称和计算定义，禁止套用垂直杯盘比阈值或据此推断分期。[视觉模块](../backend/vision/README.md) |
| 多病种范围 | 糖网和 AMD 当前只提供 FLAIR 研究性匹配分数。糖网转诊、黄斑水肿评估和疑活动性 AMD 转诊各自定义输入、标签和验证集。白内障与干眼先做检查导航。新收录的科普条目只扩展问答覆盖。 |
| 引用、签发与治疗 | 引用校验只核对正文知识陈述的出处。拟建业务另存医生对原图和病例的复核、修订、签发记录。助手释义当时有效的医嘱，改药或调整治疗请求交接诊医生。危险症状直接展示机构确认的急诊指引，无需等待模型或报告。[报告模块](../backend/report/README.md) |

## 试点启动会需要定下来的事

下表各项目前均**待确认**。“牵头角色”用于分工，启动会上需落实到姓名。会后由产品负责人把决定、适用范围、确认人、日期及附件位置填入末尾记录。

| 事项 | 牵头角色 | 会后必须能回答的问题 |
| --- | --- | --- |
| 服务范围与接收能力 | 产品、试点科主任 | 首个采集点和转诊接收科室是哪两个？纳入哪些成人、哪些设备和拍摄视野？谁负责当班阅片、急症交接和逾期追踪，每日能承接多少例？ |
| 标注与结局 | 青光眼专科负责人 | 何种可见征象触发复核？双眼、多张照片、补拍仍失败如何登记？谁独立盲读、谁裁决分歧？分别用什么记录确认“影像值得转诊”和“临床最终诊断”？ |
| 模型放行与停用 | 临床、统计、算法负责人 | 在看盲测结果前锁定目标漏转率、可接受误转量、样本量依据和通过条件。哪些病例用于校准，哪家机构或哪批设备留作独立测试？谁有权停用并安排受影响病例重读？ |
| 数据与准入 | 机构数据、法规负责人 | 哪些用途已获授权？原图、病史、发给文本模型的内容、日志和备份分别存在哪里、谁能看、保留多久？哪些外部端点获准使用？按研究、影子运行和实际诊疗分别核实伦理及监管手续。 |
| 业务验收 | 运营、临床负责人 | 先测现行人工流程的阅片耗时、复核容量和到诊率。约定到诊观察窗口，区分已接单、已到诊、等待和失访。漏转率以参考标准确认应转的病例为分母，未知结局单列。 |

## 首轮工作如何交付

| 接手人 | 下一份交付物 | 验收方式 |
| --- | --- | --- |
| 产品与临床 | 一页试点协议、一张逐眼标注表、转诊接收与异常联系人 | 用一例双眼结果不同的病例走读，采集、阅片、接收三方都能指出自己的下一步。 |
| 算法与统计 | 旧分类和分割权重版本、处理器、标签、工作点选取规则及新旧方法配对评估方案 | 患者双眼和复诊记录同组。现有权重用 REFUGE 微调过，同源回放用于回归。独立病例分别报告漏转、误转、弃判和复核量，保存分歧样例。[模型来源与对照方案](眼科业务升级路线图.md) |
| 工程与运营 | 用合成病例演示采集、补拍、人工签发、转诊和回执 | 右眼有结果、左眼重拍仍不可判读时，追问和导出应逐眼一致。重复提交只产生一份最终结果。模型下线时可转人工，未到诊病例始终有跟进人。 |

**交接顺序。** 工程可先用合成病例联调。真实病例按已确认的数据用途和审批范围进入评估。候选模型先做不影响诊疗的影子运行，按锁定的标准复盘后，再决定是否在指定机构和设备上启用。严重漏转、眼别错误或越权签发触发暂停，保留版本和病例清单，由临床负责人组织复核。

## 2026-11-25 交接约定

业务负责人维护机构名单、接收科室、日容量和急症联系席。工程负责人按名单配置机构和获准模型端点；名单是全量替换，移除成员即时影响病例调阅。阅片人员按眼别登记检查来源、日期和解读，核对病例版本后模拟签发。撤销时填写原因；追溯历史签发应同时检查最新版本。协调人员登记到诊回执和待跟进病例。

青光眼继续采用冻结基线。其他眼病先收集专科参考检查和结局。软件验收统一使用合成数据，性能、费用和临床结论分别以实测、账单和经授权的临床评估为准。[完成与未完成清单](眼科业务升级路线图.md) · [工具及恢复操作](../tools/README.md)
