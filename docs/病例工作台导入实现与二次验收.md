## 已实现的方案

1. 在工作台点击「导入已有分析」，可补充当前病例或当前手工草稿；未选病例时创建新草稿。在报告结果旁点击「用于病例草稿」，会直接预选该分析。
2. 选择当前账号最近 100 份分析中的一至两份，确认每份眼别及采集时间、设备。旧资料未知就保留缺项；不从名称、分数或报告时间推断。已归档眼别与所选眼别不同，服务端拒绝改绑。
3. 选择备注保留、追加或明确替换，查看服务端生成的合并预览。人工任务、所见和既有采集默认保留；研究模型指标进入独立来源区，不填成「人工所见」。
4. 确认眼别对应及合成用途后，只生成待复核草稿；不自动签发或转诊。已有签发与转诊继续留在原快照。取消预览不会写入病例。
5. 「研究分析来源」可查看原值、模型版本、原报告引用状态、来源哈希及原图；正文和证据用普通文本展示。概率、面积等效 CDR、FLAIR 均不转换成分期、阳性/阴性或处置结论。

### 来源、版本与事务

- 新分析的原图按随机 ID 归档于 `backend/original_store`，原图 SHA-256 和选填采集信息、临床记录、病种保存在 reports.source_metadata。报告及会话事务失败时清理本次文件。旧记录迁移为空元数据，不补造原图。
- 新增当前账号的报告目录、结构化详情和原图接口；原图按归属和哈希核对，以不缓存的二进制附件返回。没有暴露服务器磁盘路径。
- 导入来源和原始报告被保存为 `analysis_sources` 不可变快照；`analysis_refs` 只能通过服务端导入注册。后续修订不能伪造其他报告引用。
- 预览保存 15 分钟，在确认事务中再次核对账号、目标版本、报告哈希和原图状态。幂等收据、病例当前状态、版本和审计同事务提交；中途数据库写入失败全部回滚。同预览重复确认返回首次结果，同来源没有实际变更时不增版本。
- 采集时间、设备可重新预览修订，不重复追加照片、来源或备注。明确标为真实临床数据的来源拒绝导入；未知来源须由操作者声明合成用途，声明不等于系统已核验数据真伪或获得机构准入。
- 研究来源、人工评估、签发计划分别保存。历史释义、JSON 和演练 PDF 引用对应版本；rejected、disabled、error 原状态保留，不被导入转换为通过或医嘱。

复现命令（仓库根目录）：

```powershell
npm.cmd --prefix frontend run test:screening
npm.cmd --prefix frontend run build
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests
.\.venv\Scripts\python.exe tools/serve_screening_acceptance.py --port 8127
```

最后一条启动实际前后端，但仅监听本机回环地址，在 `tmp/screening-acceptance-*` 内创建临时数据库、合成账号、原图和报告，不读取生产病例或真实 Key。打开 `http://127.0.0.1:8127/?debug=0`，可从预置对话或工作台开始走读。`AUDIT-1` 为双眼结果不同的草稿，`AUDIT-2` 为待模拟签发；存档同时包含有原图的新分析、缺原图旧报告及拒答记录。推理结果为明确标记的测试固定值，只用来验收软件链路。真实网络拔断、浏览器原生离开确认、真实设备及临床效果未作为本次自动测试通过项。
