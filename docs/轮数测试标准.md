# VERIFY_MAX_ROUNDS 测试标准

本文先固定测试口径，再记录实测结果。改动 `backend/utils/config.py` 的
`VERIFY_MAX_ROUNDS`（核查修订轮数上限）是否合适，以此文为准。

## 1. 待测参数与范围

`VERIFY_MAX_ROUNDS` 取值 **3、4、5、6、7** 五档，对照当前默认值 2。

**一轮 = 1 次改写调用 + 1 次复核调用**（`agents/verifier.py:254-287`）。此外：

- 首轮核查 1 次调用（`stage=initial`）
- 出现 `source_audit` 来源问题时，追加 1 次有界复核（`stage=source_adjudication`）
- 改写不收敛时，最多 1 次整篇重生成（`regenerate`），再复核
- 格式错误时，同一步骤内最多重试 1 次

## 2. 测试输入（固定不变）

| 项 | 取值 |
| --- | --- |
| 影像 | `samples/fundus_right_eye.png` |
| 临床记录 | `samples/clinical_note.txt` |
| 病种 | `glaucoma`（单病种，避免多病种并发干扰轮数观察） |
| LLM | `backend/.env` 的 `deepseek-v4.1-flash` |
| 检索 | `RAG_MODE=bm25`（移除向量模型的不确定性，使检索结果可重复） |

同一输入重复五次，只改变 `VERIFY_MAX_ROUNDS`。

## 3. 采集指标

逐档记录：

| 指标 | 来源 | 含义 |
| --- | --- | --- |
| `status` | `verification.status` | pass / rewritten / rejected / limited / error |
| `rounds` | `verification.rounds` | 实际执行的核查次数 |
| `initial_issues` | `verification.initial_issues` | 首轮发现的问题数 |
| `fixed` / `deleted` | `verification` | 实际改写与删除的句子数 |
| `regenerated` | `verification` | 是否触发整篇重生成 |
| LLM 调用次数 | 测试侧计数 | 成本度量 |
| 耗时 | 测试侧计时 | 时延度量 |
| 正文字数 | `content_len(summary)` | 交付内容量 |

## 4. 判定口径

对每档取值判定以下四项，**全部满足才算该档可用**：

1. **可交付**：`status ∈ {pass, rewritten}`，且 `summary` 非空、非「病例资料摘要」降级文本。
2. **有诊疗内容**：正文包含当前评估、关键依据、下一步处置三类内容（缺任一类记为内容不完整）。
3. **引用可追溯**：正文中出现的每个 `[n]` 都存在于 `evidence` 的编号范围内。
4. **无越界表述**：`verification.remaining_issues` 为空。

## 5. 选择规则

在满足第 4 节四项的档位中，选**轮数最小的**一档作为建议值：

- 轮数更大但结果相同，只增加 LLM 调用与等待时间，没有收益。
- 若最小可用档 `k` 与 `k+1` 之间出现「`k` 不可交付、`k+1` 可交付」，说明存在临界点，取 `k+1` 并记录该边界。
- 若所有档位都不可交付，问题不在轮数上限，需回到语料与检索层排查。

## 6. 成本口径

`VERIFY_MAX_ROUNDS` 是**上限**而非固定值。实际调用数取决于核查是否收敛：

- 首轮即通过：1 次核查调用，与上限无关
- 需要修订：每轮 +2 次，直到收敛或用尽上限

因此评估时分两栏：**最坏情况成本**（上限 × 2 + 1）与**实测成本**（本次实际调用数）。

## 7. 已知限制

- 单病例、单模型、单次运行，结论不可外推到其他病例或模型。
- LLM 有随机性，同一档重复运行结果可能不同；本文结果仅代表本次观测。
- 通过引用校验表示来源检查完成，**不等于**医学正确性验证或医生签发。
