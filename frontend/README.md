# 前端 · React + Vite

OcuPanel 的浏览器客户端。页面提供账号登录、会话、眼科分析、报告与个人设置。 [项目 README](../README.md)

## 本地开发

按 [安装指南](../README.md#安装指南) 准备后端并保持运行。在另一个终端从仓库根目录执行以下命令。

```powershell
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run dev
```

默认打开 [Vite 开发页面](http://127.0.0.1:5500)，实际端口以终端输出为准。`/api` 自动代理到后端的 `http://127.0.0.1:8000`。后端端口有调整时可在启动 Vite 的同一终端设置 `$env:API_PROXY_TARGET = 'http://127.0.0.1:8001'`。

从根目录运行 `npm.cmd --prefix frontend run build` 生成 `frontend/dist/`，由 FastAPI 托管。Linux 和 macOS 将命令中的 `npm.cmd` 换成 `npm`。

## 技术栈

React 18 + Vite 6，没有路由库、没有状态管理库、没有 UI 组件库。
Markdown 渲染用 Showdown（**已显式开启 `tables: true`**，默认是关的，表格会渲染成一行竖线）。

报告的引用校验面板区分“局部删减”和“核心待核实”，展开可查看删去的原句及原因。非核心内容移除后仅在全文重新核查通过时显示“引用校验通过（已修订）”。PDF 仍只对存档且状态为 `pass` 或 `rewritten` 的报告开放，旧报告不自动重新校验。

新报告可展开“通过内容的来源对照”，查看病例、资料编号或软件声明中的支持片段，并区分病例推理、一般建议及具体处置。“校验过程”展示每轮问题数量，来源归类复核有单独提示。全部条目按普通文本渲染，不把来源片段当成网页指令或正文结论。病例来源核对不代表验证原始记录真实性。

诊疗结论仍未通过时可显示“仅提供病例资料摘要”：保留输入原文和独立的影像结果，待核实的草稿表述仅在审计区显示；不启用诊断 PDF 下载，也不显示为校验通过。模型请求或格式故障继续明确报错。

## 目录与组件

病例列表支持全部、待跟进、已逾期筛选，范围为当前账号已载入的病例。等待、已接单和失访均保留跟进，超过截止时间且尚未到诊的转诊计入逾期。点击刷新可重新核对当前状态。

侧栏「病例工作台 · 合成演练」由 `components/ScreeningView.jsx` 管理。无需配置 LLM；新建默认双眼未拍，可主动点击「填入双眼示例」。检查任务支持青光眼、DR、DME、AMD 的人工登记，新任务保持未评估，不复用其他任务的结论。页面默认展示逐眼结果、当前处置及转诊跟进，移交、采集来源、操作历史按需展开。逐眼释义使用版本绑定的结构化数据渲染，可展开和收起，用户文字按普通文本展示。[逐项验证与导入方案](../docs/病例工作台验证与导入方案.md)

`components/screening/CaseForm.jsx` 负责病例与任务编辑，`CaseActions.jsx` 负责复核、模拟签发、移交及回执表单，`CaseDetails.jsx` 负责结果、释义和历史；`src/screening/caseForm.js` 保存任务目录、非破坏性表单操作及跨任务校验。任务状态变化不会删除原图引用，也不会自动添加采集或判为可疑。每例的操作表单独立，不沿用其他病例的计划。病例编辑切换、取消、离开工作台和刷新有未保存提示；临时输入不作为持久草稿保存。

请求统一经过 `api.js`，认证失效回登录。写请求重试保留原幂等键，旧版本只读。提交成功会显示操作结果与版本；后续同步失败保留已保存结果并提示刷新，不误报整个操作失败。版本冲突时保留填写内容，不能覆盖新状态。[接口与限制](../backend/screening/README.md)

表单回归：`npm.cmd --prefix frontend run test:screening`。覆盖补拍记录保留、多任务独立、空白采集状态、显式选择所见结论及未显示任务的校验。页面行为另用临时 SQLite 和实际 API 走读验证，不调用 LLM。

工作台「导入已有分析」和报告旁「用于病例草稿」接入同一 `screening/AnalysisImport.jsx`。选择来源、确认眼别和采集缺项、预览备注合并后确认，保存为新草稿版本，不重新推理或自动签发。`AnalysisSources.jsx` 按需展示研究指标及原图，人工结论独立保留。全新草稿按导入病种建立任务，不额外强加青光眼；已有手工草稿保留所选任务。旧原图缺失时显示提示并阻止原图复核。签发、转诊、移交和回执的未提交输入也已纳入离开保护。原报告正文用普通文本展示。[两轮验收](../docs/病例工作台导入实现与二次验收.md)

├── api.js                       # 接口封装：统一带 Bearer 令牌，401 自动退回登录

## 页面状态约定

主视图状态是 `App.jsx` 里的 `view`，五种取值：`'welcome' | 'chat' | 'report' | 'screening' | 'settings'`。工作台通过离开回调保护未保存的病例编辑；其他视图继续沿用原有导航。

- **欢迎页只在首次登录 / 无对话时出现**，它没有输入框，只是引导。点「新建对话」必须进
  `ChatView`（`setView('chat')`），删除当前会话后同理——**绝不能把用户丢回欢迎页**，
  否则看起来像按钮没反应。
- **退出登录有两个入口**：侧栏底部的图标（`.nav-user-logout`）与「个人设置」里的按钮，
  都要走 `handleLogout`（confirm → `/account/logout` → resetToLogin）。
- `.nav-user` 是 `<div>` 容器而非 button（内部有两个按钮 `.nav-user-main` / `.nav-user-logout`），
  改结构时注意别嵌套 button。
- 侧栏「用户区」不是纯展示：点名字进设置页。

## 界面功能

**1. 登录 / 注册** — 用户名 + 密码，同一张卡片切换。登录态是随机令牌（存 SQLite `sessions`，
7 天有效），不是 JWT，所以注销能真正失效。退出只清除本机登录态，**服务端数据一条都不动**，
重新登录后对话与报告都还在。

**2. 对话（智能问答）**

- 首页是带建议卡的欢迎页，点卡片直接把问题发出去；
- 对话记录存在服务端，换设备登录也还在，重启服务不丢；
- 首条消息自动给会话起名，侧边栏不再一水儿「新对话」；
- 每个账号只能看到自己的会话，访问别人的会话一律 404。

**3. 生成报告**

- 在提问栏的「+」菜单或欢迎页点「眼科影像分析」进入，上传眼底图（支持拖拽）+ 填临床记录；
- 提交影像后，根据所选病种运行视觉分析和对应专科 Agent，多病种由 Director 汇总，随后校验正文引用。影像模型指标单独展示。默认分析青光眼，DR 与 AMD 需要安装可选 FLAIR 依赖。
- 会话内可展开青光眼分割叠加图，结合颜色和面积等效杯盘比的计算方法复核测量。预览图保持原始比例，最大宽度为 320px，最大高度为 280px，窄屏下随可用宽度缩小。点击正文引用编号可展开对应证据。引用状态描述自动核查的结果。
- 结果**追加到当前对话**，所以生成完可以直接接着追问（报告正文本身就是上下文）；
- 校验不通过时后端拒答、不出 PDF，前端不显示「下载」按钮；
- 通过后可下载含图像、杯盘比与报告的 PDF，语言由后端 REPORT_LANGUAGE 配置。

**4. 个人设置**

- 填 API Key / 接口地址 / 模型，内置 DeepSeek、OpenAI、Moonshot、阿里云百炼四家预设；
- 「测试连通」先用一次最小请求验证 key / 端点 / 模型，**测通了再保存**，
  避免错配置存进去之后每次生成都失败；
- Key 服务端加密存储，界面只显示掩码，留空保存表示沿用旧值；
- 显示使用概况：几个对话、几份报告、其中几次因校验未通过被拒答。

## 调试抽屉

右下角「调试」悬浮按钮（`DebugDrawer.jsx`），点开能看到最近 50 次请求：

| 字段 | 说明 |
|---|---|
| 名称 / 方法 / URL | 如「生成报告内容 · POST /api/generate-report-content/」 |
| 状态与耗时 | `200`、`ERR`（网络失败）与毫秒数 |
| 请求 | 文件名、大小、备注字数 |
| 响应 | 原始 JSON（截断 4000 字符）或 Blob 大小与类型 |

支持「复制」把全部记录导出成 JSON。

URL 参数 `?debug=0` 可隐藏调试按钮（给医生演示时用），也可以写进 `.env` 的 `VITE_DEBUG=0`，
其中 URL 参数刷新即生效；修改 `frontend/.env` 后，开发模式需重启 Vite，单服务模式需重新构建。

> 离线 mock 模式已移除。数据现在都在 SQLite 且需要登录态，
> 留一个假的 mock 层只会在排查时制造「看起来通了其实没通」的错觉。

## 环境变量

`frontend/.env`（模板见 `.env.example`，一般不用配）：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `VITE_API_BASE_URL` | 空（同源相对路径） | 只有后端在别的地址 / 端口时才需要设置 |
| `API_PROXY_TARGET` | `http://127.0.0.1:8000` | Vite 进程环境变量，覆盖开发代理目标；修改后重启 Vite |
| `VITE_DEBUG` | `1`（开启） | 右下角调试抽屉 |

## 故障排查

**页面能打开，但一提交就 `Internal Server Error`。** 开发模式下页面在 5500、接口要转发到 8000，
只起前端时页面正常（纯静态），但任何提交都会因为代理找不到后端而失败——
Vite 会返回 `500` + `text/plain` + **空响应体**，浏览器只显示一句 Internal Server Error。

`api.js` 已针对这个形态给了可读提示。判断方法：

```bash
curl.exe -s -o NUL -w "%{http_code}\n" http://127.0.0.1:8000/api/account/llm-presets
```

返回 `200` 说明后端在跑（去看它的 traceback）；连接失败说明后端没起。

**改了代码页面没变化。** 单服务模式下页面来自构建产物，改完要重新 `npm run build`；
想热更新就用 `npm run dev`。

**端口被占用（WinError 10013）。** 后端设 `PORT=8001`，开发前端设置 `API_PROXY_TARGET=http://127.0.0.1:8001`。

## 两种会话形态

初次进入与新建会话默认为普通聊天，可在欢迎页或聊天页切换为眼科助手。模式按会话保存，重新打开会话会恢复。普通聊天不注入眼科系统提示词；眼科助手使用 chat/prompts.py 的业务指令。

普通聊天和眼科助手均可通过提问栏左侧「+」打开「眼科影像分析」，欢迎页保留直接入口。上传图片与医疗报告/临床记录并提交后，进入当前聊天，自动切为眼科助手，显示生成状态和报告回复，随后可继续追问。未提交分析时只切换形态，不执行视觉模型、Agents 或产生报告费用。切回普通聊天保留已有消息。

后端的 PATCH /api/chat/conversations/{id}/mode 负责持久化形态；旧数据库在启动时迁移，旧报告会话保留眼科助手语义。详细规则见 [会话说明](../backend/chat/README.md)。llm/ 不再包含眼科提示词，分析 Agent 与聊天各自管理指令。

## 输入面板与上下文

输入面板与消息内容使用同一宽度上限（860px），文字与底部工具栏位于同一面板。发送按钮为右下角圆形向上箭头，保留无障碍名称；请求处理中显示旋转状态且不可重复发送。

输入框随换行、自动折行和粘贴增高，文本区域最高 160px，超出后内部滚动；删除和发送后缩小。Enter 发送，Shift+Enter 换行，输入法选词时不会把 Enter 作为发送。眼科助手的「+」菜单还提供「问答图谱检索」，勾选或取消勾选后菜单保持展开，选择随会话保存。影像报告使用服务端检索配置。

完整会话可在界面查看，但发给 LLM 的只是受条数、字符预算限制的上下文。普通聊天不调用视觉模型或报告 Agents，眼科追问也不自动重跑分析。

保存的报告具有通过或修订后通过的引用校验记录时，历史会话提供下载按钮。校验已关闭或旧记录缺少校验状态时仍可查看正文。页面使用 `GET /api/reports/{report_id}/pdf` 导出已保存的正文与参考资料。「个人设置 → 报告下载」可选择保存位置对话框或浏览器下载设置。保存位置功能取决于浏览器支持，偏好按账号保存在当前浏览器。

工作台可查看机构联系方式、逐眼检查依据、急症交接提示和带来源的就医导航。报告通过持久任务 API 提交并查询结果。模拟签发支持按版本撤销并保留历史。[业务交接](../docs/交接文档.md)
