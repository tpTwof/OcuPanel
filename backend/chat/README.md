# 会话形态

每个会话有独立的 mode：general（普通聊天）或 ophthalmic（眼科助手），新会话默认 general。

- api.py：会话、消息、形态 HTTP 路由。
- service.py：读取会话形态和历史，选择业务系统提示词，通过 LLMClient 请求回复。
- prompts.py：眼科助手系统提示词，只在 ophthalmic 形态注入。
- models.py：ChatMode、创建/修改会话和消息请求。

普通聊天的请求不注入业务系统提示词。眼科助手形态不会自动运行视觉模型或 Agents，只在用户明确提交图片与临床记录时执行分析。分析接口将当前会话切为 ophthalmic，保存临床记录及报告回复；后续追问带上该会话历史。

PATCH /api/chat/conversations/{id}/mode 接收 {"mode":"general"} 或 {"mode":"ophthalmic"}，只允许修改当前用户自己的会话。切换保留所有历史，不会清除之前报告；返回普通聊天也不代表历史医疗内容被遗忘。

SQLite 启动迁移增加 conversations.mode，已有报告消息的旧会话初始化为 ophthalmic。迁移幂等，用户之后主动切回 general 不会被启动迁移改回。

聊天直接使用 LLMClient，不依赖完整报告生成器。llm/ 只处理传入的消息与可选系统指令；分析 Agent 的语言指令归 agents/prompts/language.py，PDF 的展示语言归 report/settings.py。

不同会话不共享消息上下文，仅共享该账户的 LLM 配置。眼科形态每次发送都传入系统指令，系统指令不作为消息写库。模型请求失败返回 502，已写入的本次用户消息仍保留。没有消息流式输出或自动历史摘要。

## 聊天上下文与回复预算

完整消息保存在 SQLite，发给聊天模型的历史使用 chat/context.py 的窗口选择，不删除存储记录，不产生额外摘要调用。

| 配置 | 默认值 | 含义 |
|---|---|---|
| CHAT_HISTORY_MAX_MESSAGES | 20 | 历史消息条数上限，约 10 轮；固定报告计入条数，当前问题和系统指令不计入条数 |
| CHAT_CONTEXT_MAX_CHARS | 20000 | 系统指令、当前问题与所选历史正文的总字符预算 |
| CHAT_REPORT_MAX_CHARS | 6000 | 眼科形态最多保留最近一份报告的字符数，同时不超过剩余预算一半 |
| CHAT_MAX_OUTPUT_TOKENS | 2048 | 单次聊天回复的 max_tokens，不影响专科与报告生成 |

在 backend/.env 中覆盖后重启后端。字符预算不是精确 token 计数，不同供应商分词规则、消息封装开销和模型上下文上限不同，仍需按所用模型调整。输出 token 上限可能截断过长回复，客户端目前不提供 finish_reason 展示。

普通形态只选择连续的近期消息，不截断普通历史消息；一条历史消息超过剩余预算时停止向前取。眼科形态额外固定最近报告，长报告尾部带“报告节选”标记，并排除其他旧报告。更早的病例细节和对话可能不在本次输入中，不等于模型具有永久记忆。

当前问题加系统指令已超过预算，或无法保留必要报告上下文时返回 413，请缩短或分段发送；这类输入不会被保存为新消息，也不会调用模型。窗口选择仍从完整会话记录计算；若会话存储量很大，数据库查询和界面加载仍需后续分页，与 LLM 输入 token 预算是不同问题。
