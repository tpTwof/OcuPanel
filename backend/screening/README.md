# 逐眼阅片与转诊演练

本模块落实交接文档的首轮工程交付：使用合成病例走通采集、补拍、人工复核、模拟签发、转诊和回执。**仅用于合成联调**，不接收真实影像，不调用视觉或文本模型，不提供临床签发，不改变原有研究报告管线。默认病例归创建账号。配置机构成员后，新建的机构病例可由同机构采集、阅片、协调账号按角色协作。历史私有病例继续按创建账号读取。签发身份为演练账号。

## 数据与状态

`models.py` 定义版本 1 契约。一次检查必须包含机构、就诊编号、患者分组编号、成人年龄、跟进人和左右眼。每眼保存合成原图引用、采集时间（含时区）、设备、视野和各病种任务。原图引用必须使用 `synthetic:` 前缀；这是演练引用，不代表已上传或实际读取影像。界面与 API 均可记录青光眼、DR、DME、AMD 的人工演练任务；这不增加影像模型能力。新建表单默认未拍；只有显式记录合成采集才追加引用。新增任务保持未评估或未拍，不能继承原任务结论。

任务状态分别为 `not_captured`、`not_assessed`、`ungradable`、`gradable`。不可判读必须填写原因及下一步；只有可判读任务允许 `suspect` 或 `no_target_signs`。未拍、未评估及不可判读均不能作为阴性。双眼各自保存结果，补拍通过追加采集记录登记。

草稿 `draft` 经原图引用与病例核对进入 `reviewed`，再保存 `kind=simulated` 的签发记录进入 `signed`。操作者取自登录账户，客户端不能指定签发人。存在未评估任务时不能模拟签发。未拍与不可判读可携带明确安排签发演练计划。修订会生成新的草稿版本、清除当前复核及签发，但保留旧版及转诊记录。

转诊单绑定具体 `signed_revision`，同时保存眼别、去向、跟进人、期限。每个签发版本只有一份转诊单。回执分为等待 `waiting`、已接单 `accepted`、已到诊 `arrived` 和失访 `lost`；已接单不等于到诊，失访后可再次接单或到诊，到诊是终态。旧版本转诊仍可跟进。人工移交更新未到诊转诊单的跟进人，不改写旧版签发计划。

紧急交接标记和常驻提示独立于模型或签发，**当前没有经过机构确认的急诊规则、电话号码或症状分类器**。真实业务必须另行配置并验证机构路径，不得把标记视为自动分诊。

## 接口

全部沿用 Bearer 认证及账号隔离，响应不缓存。接口前缀 `/api/screening`。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET / POST | `/cases` | 最近 200 例 / 创建合成检查 |
| GET | `/cases/{id}?revision=N` | 当前状态或不可变历史快照 |
| POST | `/cases/{id}/commands` | `revise`、`review`、`sign`、`refer`、`receipt`、`handoff` |
| GET | `/cases/{id}/context?revision=N` | 绑定版本的逐眼释义与结构化追问上下文，不调用 LLM |
| GET | `/cases/{id}/export?revision=N` | 完整 JSON 快照，含审计和版本来源 |
| GET | `/cases/{id}/pdf?revision=N` | 已模拟签发版本的演练 PDF；未签发返回 422 |

创建请求为 `{idempotency_key, examination}`。操作为 `{action, idempotency_key, expected_revision, ...}`；各操作字段见 Swagger。未知字段直接拒绝。相同账号的幂等键对应请求指纹和首次结果：同键同内容返回原收据，同键不同内容返回 409。版本冲突也返回 409，刷新后再提交。重放结果可能比当前状态旧，因此操作后应重新 GET 当前病例。客户端请求失败时保留同一请求的幂等键，可刷新列表查询是否保存成功。

`repository.py` 使用应用 SQLite 的 `screening_cases`、`screening_versions`、`screening_requests` 三表。写操作通过 `BEGIN IMMEDIATE` 串行校验版本，并将当前状态、不可变快照及幂等收据在同一事务内提交。成功响应丢失后重试不会追加重复事件。这里没有异步推理任务或恢复推理的工作队列；这些操作是同步、无模型的事务，不保证旧报告生成接口的幂等性。

`context` 同时提供结构化逐眼结果与 `presentation.py` 的确定性正文。工作台用结构化字段展示简洁、可收起的释义，不直接显示 Markdown 原文；PDF 继续使用同一快照的确定性正文。JSON 保留完整字段；PDF 展示逐眼状态、采集来源、计划和转诊版本。PDF 标记合成演练，不伪造引用校验通过或医生签发。临时文件发送后删除。历史快照不随修订变动。

第一轮交互修订及导入设计见[工作台验证记录](../../docs/病例工作台验证与导入方案.md)。后续已实现报告原图归档、导入预览及确认接口，并补齐操作输入保护；当前完成边界和两轮验收见[导入实现与二次验收](../../docs/病例工作台导入实现与二次验收.md)。

备份原有数据库时包含以上三表。当前没有演练记录清理接口；不要在演练字段录入真实个人信息。实际病例准入、机构与角色授权、访问审计、数据留存和撤权删除流程仍需建设及机构确认。

## 分析导入与配对评估

### 已保存分析导入

工作台和报告结果旁均可打开导入预览，可向新草稿或当前病例补充最多两份分析。每份必须明确眼别；已归档眼别不能自动改绑。采集信息缺失时保留缺项，备注可选择保留、追加或明确替换。已有人工任务及所见默认保持原样，新任务只进入未评估状态；概率、CDR 和 FLAIR 不转换为人工诊断或分级。

接口为 `POST /api/screening/imports/preview` 和 `POST /api/screening/imports/{preview_id}/confirm`。预览保存合并候选及来源快照，有效期 15 分钟，新预览请求清理过期行。确认须带幂等键、眼别核对及合成用途声明，在同一事务中校验所有者、目标版本、来源哈希和原图状态，保存草稿、历史版本、审计和收据。重复确认只产生一次结果；重复导入同一来源且无字段变更时不增版本。预览后来源或病例变化返回 409，需重新预览。

导入后的 schema_version 为 2。`analysis_sources` 由服务端生成，包含原报告、原始指标、校验状态、模型来源、眼别、原图哈希、导入人及用途声明。`eyes[].analysis_refs` 引用这些报告 ID，不能通过普通创建或修订伪造。缺原图时，允许有来源引用的任务保持未评估，但不假造采集记录；缺原图或采集信息时不能记录原图已复核。时间或设备可通过重新选择同一报告、补齐后再预览修订，不重复追加来源和照片。

有变化的导入只创建待复核草稿，清除当前复核和模拟签发；旧签发与转诊历史不改写。释义、JSON 和演练 PDF 保留对应版本来源，与人工结果分开展示。原报告的 rejected/disabled/error 不变成 pass。明确标记为真实临床数据的来源被拒绝；未分类的历史来源须由操作者明确声明合成用途，不等于临床准入审批。[两轮验收](../../docs/病例工作台导入实现与二次验收.md)

### 配对评估工具

`evaluation.py` 接收预先锁定工作点的新旧方法配对决定，不运行或训练候选模型，也不选择临床阈值。按患者检查分组泄漏和重复眼别任务，只评价 test 集；分别输出病种及机构、设备分层结果。

灵敏度、特异度仅在参考标准已知且非弃判记录上计算，必须同时报告覆盖率、弃判数、阳性弃判数、误转数及复核量。流程漏转率分母为参考标准确认应转的全部记录；去向未决时返回缺失值和上下界，不把等待当成无漏转。未知参考结局单列。区间按患者整组 bootstrap，双眼和复诊不会被拆开；小样本区间不能用于宣称验证完成。此工具不估计人群抽样核验校正，不替代事前统计方案。

完整合成回放及命令见[升级验收](../../docs/升级验收.md)和[工具](../../tools/README.md)。

## 机构共享与专科记录

机构管理员在本机配置角色、容量与接收联系方式。成员可读取同机构新建病例及其指定版本的导入原图。阅片角色可复核、模拟签发并填写原因撤销，协调角色处理移交与回执。读写按当前成员身份检查。病例记录紧急症状时必须保留急症交接标记。逐眼参考检查记录日期、来源和解读，可判读 DME 的模拟签发检查同眼 OCT。[配置与合成数据](../../tools/README.md)
