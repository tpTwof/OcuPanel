# 报告分析 Agents

- SpecialistAgent：接收病例事实、使用注入的检索工具获取专业证据、根据职责生成分析并验证响应非空且不是调用错误。
- DirectorAgent：综合各专科结果与证据，接收校验反馈后重新生成；调用不共享聊天历史。
- CitationVerifier：核查引用，必要时调用重写并复核，再通过 regenerate 回调要求 Director 重写；有次数上限，失败返回明确状态。
- ParallelOrchestrator：并发运行独立专科 Agent，返回角色到分析文本的映射。

这是职责明确、工具受限的 Agent 工作流。专科拥有检索工具，校验 Agent 拥有核查/重写/复核循环；目前没有任意工具调用、长期记忆或通用自主规划。角色可以共享 SpecialistAgent 实现，无需复制一份类。没有实现的协作模式会明确报错。

llm_call 和检索工具通过构造参数注入，便于离线测试。Agent 不读取上传文件、不写 PDF、不访问账户数据库。数据来源是当前请求的病例事实与证据；不能把分类概率推断成严重程度。

## 可调用工具

专科 Agent 支持 JSON 工具操作 search_evidence(query)、read_evidence(id)，以及 final(text)。模型也可直接输出最终文本。每次执行最多三次工具操作，超过上限中止；工具仅能读取当前请求、最终证据包中的资料。每轮操作和工具结果作为请求内上下文返回给模型，任务结束后不保留记忆。

专科和 Director 都检查引用编号，不能引用未提供的证据。引用语义是否支持陈述仍由 Verifier 判断。模型请求超时与网络重试由 llm.client 的配置控制；工具循环上限单独控制。没有增加任意文件读取、命令执行或未授权网络访问。

## 校验代码分层

- verifier.py：CitationVerifier 的调用与复核循环，输出通过、修订通过、拒答或错误状态。
- prompts/verification.py：核查/修订系统提示词、证据展示和任务提示词构建。
- tools/text_revision.py：原句定位、定点替换、内容长度及启发式内容丢失检查。
- tools/json_response.py：模型响应 JSON 解析。

校验 Agent 只核对外部知识引用，不保证病例测量值本身真实。文本修订工具不单独判定报告通过；修改后仍需复核。正文长度阈值在修订后仍有问题时用于触发一次重生成，不是所有通过报告的最低长度限制。

本次拆分保留现有运行策略。离线回归测试覆盖文本工具、修订复核、重生成与拒答路径，不调用外部模型。
