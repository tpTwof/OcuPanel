# 报告分析 Agents

每个所选病种基于本病种视觉结果和共同临床记录检索。报告按片段 ID 去重并统一编号，专科只收到本病种召回的片段。青光眼、糖尿病视网膜病变（DR）和年龄相关性黄斑变性（AMD）各有一个分析角色，只运行用户选中的病种。职责维护在 [roles.py](roles.py)。

| 组件 | 输入与职责 | 输出 |
| --- | --- | --- |
| SpecialistAgent | 按病种解读病例事实，可在本次报告的证据包内搜索和读取资料 | 单病种直接成稿，多病种返回专科分析 |
| DirectorAgent | 多病种时综合专科分析、病例事实和证据，依据校验反馈修订 | 一份报告草稿 |
| CitationVerifier | 检查外部知识的引用编号和证据支持，必要时修订、复核或请求一次重生成 | 正文及校验记录，或拒答原因 |

ParallelOrchestrator 是普通执行器，多病种时用线程池运行专科。校验响应中的问题条目必须能解析出原句和有效判定；JSON 或条目结构不符合约定时，带原文、原证据与字段错误提示重新核查一次，仍无效则返回校验错误。不丢弃无效条目，也不把不合法响应作为无问题通过。修订删空正文时拒绝交付。校验要求整篇重生成时，单病种交回该专科，多病种交回 Director。

`tools/verification_response.py` 严格解析问题列表。`claims` 仅包含 `partial`、`unsupported`、`uncited`；已被支持的句子应从列表省略。错误中的字段路径与预期类型写入 `failure_detail`，不包含响应原文；`format_retries` 记录本次报告累计格式重试次数。每次核查最多额外调用一次模型，网络错误和空响应不走格式重试。

专科工具支持 `search_evidence`、`read_evidence`，默认最多执行三次。视觉模型负责测量及预测，Verifier 只检查知识引用。校验配置与交付行为见[报告流程](../report/README.md)。

最终报告先给“初步评估结论”，再列关键依据、下一步和简短局限。单病种成稿与多病种综合共用 `prompts/report.py`：有逐眼数据时分别说明来源和判断，不以对侧照片推断未拍眼；区分已完成检查、尚未提供的信息和由医生决定是否补充的项目，提出重复检查须有明确理由。初步评估须由病例与证据支持，不能被泛化的“需综合评估”替代，也不强制输出确诊、分期或未经支持的处置。

开头的医学解释应在该分句标注依据，不把引用全部放到后文。来源定位接受正文中实际存在的加粗分句片段；一般建议的数量检查忽略列表序号，实际剂量或周期仍检查。适用范围说明可关联证据原始 `scope`、地区、版本等元数据，医学结论仍核对条款正文。

病例事实或病例推理的来源条目遗漏病例指针时，由程序关联本轮已有输入快照；软件边界关联声明快照。这是来源元数据补齐，不自动证明语义正确，也不免除病例推理所需的外部依据。适用范围摘录无法逐字定位时可关联对应证据的完整原始范围快照，医学知识的外部引文仍要求正文片段存在。

## 按影响范围修订

校验按语义支持判断，不要求正文逐字复述条款。`impact=core` 表示涉及本例诊断、疾病排除、分期或处置，`local` 表示可整句移除且不改变结论的背景说明、重复解释或无关条款。缺失影响分类时兼容旧响应并按 core 处理；未知引用编号始终按 core 处理，不能被模型降为 local。

普通修订后仅剩 local 问题时，不为这些说明重新生成整篇报告，而是尝试一次局部删除。只删除可唯一精确定位、位于句子边界且互不重叠的完整问题句，不使用模糊定位；删除后再核查全文。通过后仍使用 `rewritten`，记录 `local_cleanup=true`，`fixed` 保存完整原句、原因及 `method=local_omission`。核心问题未解决、无法安全定位、删空正文、复核失败或调用出错时仍扣留正文。原句和新句仅空白不同不计为修复。

## 来源与分句校验（policy_version=2）

报告将原始临床记录与结构化视觉结果组成的 `case_context` 直接送入核查和修订，不再要求指南证明某位患者的测量值。来源类别 `basis` 分为病例事实、外部医学知识、病例推理、一般性建议、具体处置、软件能力边界和资料范围限制。病例的简单汇总及明确不作因果推断的声明，不因缺少外部引用而失败；新医学关联、确诊/排除/分期及具体检查、剂量或随访安排仍要有相应依据。病例推理允许由病例与诊断要素共同支持，不要求资料逐字描述同一患者。

问题 `quote` 按最小完整分句定位。修订只允许修改本轮点名的分句，保留可直接匹配的原始病例片段。定位容忍空白及成对的简单 Markdown 标记差异，禁止按句首推测长度，避免截断、错位和无意义片段。位置或结构错误带反馈重试一次；支持不足则进入正常修订流程，不混同为网络故障。原文中每个已使用的引用位置都要有通过内容的来源对照。

报告核查同时返回 `grounding`，条目保留通过的分句、来源类别、引用编号、支持片段及解释。`statement_id` 按本轮正文位置关联真实文本，避免模型另抄一份改词的“原句”；未提供位置时仍可逐字定位。病例与软件声明可直接引用来源标识，代码关联真实完整快照并标记 `source_snapshot`，不把模型转述当作原文。外部证据片段仍检查实际编号及逐字出处，病例推理要求病例与证据双向关联。不能把带数量或明确周期的具体处置标成一般性建议绕过引用。来源对照不足转成待修订问题；来源归类争议在改正文前最多复核一次，不无限重试。来源存在性由代码检查，语义蕴含、类别与适用性仍依赖模型，不代表临床准确度验证。

`source_manifest` 保存本轮病例上下文快照、证据 ID/章节与内容哈希及软件边界；`review_log` 记录各阶段的正文版本哈希和问题，`fixed` 记录实际删改，`reference_links` 记录最终正文的编号位置，`final_text_sha256` 关联交付正文。重生成失败保留前轮问题与审计记录，不交付失败草稿。会话、存档及 PDF 延续同一正文及通过状态，旧报告不自动升级或重新校验。

正文引用使用独立的整数标记 `[1][2]`。负号、未知编号及组合/范围写法不能绕过编号检查，会进入修正路径；不会因模型漏报而直接通过。
