# 初始 MedChat · 上游业务基线

## 更改了哪些

- 建立以青光眼为主的视觉辅助分析流程，输入彩色眼底照片和可选临床记录。
- 运行青光眼分类和视盘视杯分割，将模型输出、杯盘比和临床记录整理为病例上下文。
- 报告接口安排六个专业角色撰写分析，由 Director 产出综合报告。
- 提供浏览器查看结果、就病例追问和导出 PDF 的入口。

## 记录范围

以仓库保留的 MedChat 上游阶段为基线。首批前后端功能来自 2025 年 6 月 3 日，业务细节以 OcuPanel 分支化之前保留的上游实现为准。上游启动示例和 Web 接口的角色数量可以不同，本文描述浏览器报告流程。

## 业务模块

| 模块 | 当时的功能与用户可见结果 |
| --- | --- |
| 病例录入 | 用户提交一张眼底照片，可附临床备注。报告围绕青光眼展开，页面没有病种选择。 |
| 青光眼影像分析 | 分类负责输出预测，视盘视杯分割负责提供分割图和杯盘比所需数据。视觉输出被整理成文本，随备注交给各角色。 |
| 专科分析 | 报告接口使用眼科医生、验光师、青光眼专科医生、全科医生、眼科技师和药师。六个名称套用同一份提示模板，从各自专业视角写子报告。 |
| 综合报告 | Director 读取子报告，归纳主要发现和建议，生成面向用户的综合正文。浏览器以综合报告为主要结果。 |
| 参考资料 | 病例摘要和专科输出主要来自影像结果、用户备注和模型生成。上游没有后来的本地证据包、引用核查、自动修订和依据不足拒答机制。 |
| 会话和配置 | 服务端用环境变量提供模型凭据，追问依赖进程内会话缓存。缓存会过期，服务重启后不能像 OcuPanel 一样通过账户恢复持久化会话。 |
| 查看与导出 | 浏览器可查看综合正文和分割结果，随后进行追问或生成 PDF。持久化报告库、按账户授权下载历史 PDF 是后续版本的能力。 |

## 业务流程

眼底照片与备注 → 青光眼分类和分割 → 计算杯盘比并生成叠加图 → 组织病例上下文 → 六个角色分别撰写子报告 → Director 综合 → 浏览器展示 → 追问或导出。

以普通上传为例，用户只提交一次影像。各角色从自己的视角解释同一份病例输入，Director 的正文是面向用户的汇总，分割图和杯盘比由视觉流程提供。追问基于该会话中的报告和消息。

## 适用范围

这是上游软件行为的基线，可用于跟踪后来新增的账号管理、证据与引用、多病种和历史报告功能。上游示例和项目设计记录没有为后续 OcuPanel 变更提供临床验证。
