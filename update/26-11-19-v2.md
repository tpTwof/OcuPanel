# 2026-11-19 v2 · 报告校验、归档和历史导出

## 更改了哪些

对照[同日 v1](26-11-19-v1.md)。本轮于 11 月 19 日开始，最终回归于北京时间 11 月 20 日完成。保留 Python 确定性执行所选视觉检查、各专科独立检索撰稿、单病种直接成稿和多病种按需综合。此次修复集中在哪些结果可以交付，以及历史报告能否按原样找回。

| 环节 | v1 行为 | v2 行为 |
| --- | --- | --- |
| 上传 | 文件选择器接受所有图片，服务端只接受 JPG、JPEG、PNG 后缀 | 选择器和拖放与服务端支持的后缀一致，替换图片或离开表单时释放预览 |
| 全部病种缺少证据 | 仍调用模型撰稿，随后拒答 | 开启引用校验时，完成检查和检索后直接返回拒答原因及已有指标，省去撰稿和校验的模型调用 |
| 校验 | 损坏的问题条目可能被跳过，修订删空正文仍可能通过 | 问题原句、判定或引用字段格式异常时返回校验故障；无有效正文时拒答 |
| 保存 | 报告、分析请求、回复和标题分别写入，直接生成 PDF 的存档缺少叠加图 | 两种生成入口共用归档。关联会话的正文请求在同一 SQLite 事务里写入报告、两条消息和标题，归档异常时清理本次新增的图像文件 |
| 取图 | 通过登录检查后按文件名取图 | 按当前账号检查报告与图像的关联；不属于该账号或文件缺失均返回 404。注销时释放页面缓存的分割图 |
| PDF | 下载取决于拒答标记，直接生成和历史导出使用不同的图像来源 | 两个入口都渲染当前账号的存档，PDF 标出引用校验结果。新生成的直接 PDF 和之后导出的历史 PDF 均可带上同一张归档叠加图 |

## 端到端行为与历史兼容

1. 用户选病种并提交眼底图。视觉模块执行青光眼分类和分割，DR 和 AMD 同选时共享一次图像编码。损坏图片或模型不可用仍中止整单。
2. 各专科使用各自的视觉结果、共同备注和本病种证据。仅部分病种缺少资料时，保留已有病种的证据，并标明缺口。单病种由专科成稿，多病种再由 Director 汇总。
3. 引用核查针对正文的外部知识陈述。原始影像指标、模型来源、引用证据和校验状态分开存档，拒答时仍可查看已有指标及原因。
4. PDF 只接受有正文、未拒答且留有 pass 或 rewritten 状态的报告。关闭校验或历史记录缺少通过状态时，原会话仍可阅读，PDF 请求返回 422。旧报告有通过记录但缺少结构化指标时，沿用历史正文及原有杯盘比。早期直接生成 PDF 时已经丢失的叠加图无法从存档补回。

## 分层和文件整理

报告服务负责归档和文件交付，视觉执行、专科撰稿和引文核查继续由各自模块负责。移除没有读写方的预留建表逻辑、轨迹开关及缓存时限配置；已有 SQLite 表没有删除。原先放在根目录的业务盘点和改进建议已归入[审阅记录](../docs/README.md)，原始判断按日期保留。旧架构图已标注年代与适用范围。

## 验证范围

后端 60 项离线测试全部通过，其中本轮新增 6 项。回归覆盖病种路由、全单缺证据、损坏的校验响应、空正文、归档回滚、账号取图、两种 PDF 入口及旧报告导出。测试使用临时 SQLite 并实际渲染 PDF。前端通过 Vite 生产构建。模型调用使用测试替身；真实模型端到端耗时、浏览器人工交互及临床准确性未在本轮测量。
